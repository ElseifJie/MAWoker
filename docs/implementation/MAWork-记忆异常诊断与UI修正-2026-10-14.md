# 记忆异常诊断与 UI 修正

基于 main `d4aca03`，处理本轮四项验收反馈。

## 实际问题

只读查询截图所示记忆库及远端条目确认：卡住的是一个 edit 写入，处于 repairing，而非仍在运行的 Dream。写入预期 170 字节，GET 正文返回 169 字节，少一个尾部空白；远端 content_sha256 与预期内容哈希完全一致。原代码用正文逐字比较，误判写入失败并进入隔离。八条记忆串行读取约 1.8–1.9 秒，单条约 335 毫秒；本次长期卡住的直接原因是误判后的待核验状态，不是模型仍在执行。

后台 advance 在检查 repairing 前先检查 sending，反复保存同一个隔离状态并覆盖原始原因，实际状态 revision 已达 98034。UI 又把 repairing 算作正在运行，持续轮询并显示“自动整理正在运行”，与实际 edit 待核验不符。

截图的 ARTIFACT_SYNC_FAILED 属于成果文件同步，和记忆维护是两条链路。此次不把真实成果同步失败伪装成成功。

## 修正

- 写入核验及修复：核对路径和远端内容哈希，缺少哈希时才使用精确正文比较；不 trim 写入内容、不盲目重发未知写入。
- 待核验状态不自动推进、不反复保存，也不占据后台每批 20 个任务名额。
- 记忆页不将待核验显示成运行中；停止其自动轮询，保留只读与“修复”。排队保存/删除转入待核验时不报成功、不清除编辑内容；明确修复并确认完成后才更新编辑基准或清除已删除内容。
- 对话页恢复适度弹性左右留白，移除常规后台同步、用量统计与回合编号提示；保留真正的失败/等待补充信息和唯一结果摘要。
- 记忆详情合并重复维护提示，存储 ID 收入详情，缩小并居中空状态；文件名隐藏格式扩展名，生成的会话文件显示时间摘要，完整文件名、路径和层级仍可访问。

## 验证与边界

五项初始回归先失败后通过；一次范围审查发现排队操作转待核验时误报成功，补充保存/删除两项转移回归并观察失败后修正、定向复核通过。

最终受影响范围一次验证：41 文件、516 测试通过（56.58 秒），涵盖 Web、记忆服务/API/数据库、相关删除与隔离恢复。真实隔离 PostgreSQL 下，两个恢复请求只有一个 CAS 成功，不重发远端写入；6 项 PostgreSQL 争用测试通过。所有工作区构建（含类型检查）、修改文件 ESLint、Prettier、diff 检查通过。临时 PostgreSQL 已停止；不进行截图/浏览器视觉检查，不启动开发服务，不重复全项目无关测试。

本轮只读定位实际资源，没有直接修改应用数据库或远端记忆。更新服务后，原待核验操作可通过记忆页“修复”按已确认哈希恢复；内容无法核验时仍保持隔离。用户已有 material-picker 测试格式变动及 diagrams 保持原样，不纳入提交。
