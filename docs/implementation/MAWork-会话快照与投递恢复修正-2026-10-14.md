# 会话快照与投递恢复修正

起点 main `e5bceb4`。用户反馈新任务卡住，已保存的任务正文未按用户消息显示，系统提示也与正文混在一起。

## 根因与修正

远端会话已创建，尚无用户消息。真实快照包含助手 ID/版本、模型、技能、工具、环境 ID/type/config.type，但没有环境 scope 描述字段。原解析将 scope 当必需字段，误判快照不完整；创建阶段的阻断又被保守记录成未知投递，导致后台不继续发送。

scope 缺省现在保留为 null，不阻止其余完整身份字段核验；提供错误类型的 scope、缺失模型/工具/技能或身份不匹配仍被拒绝。不会用当前助手配置冒充会话快照。

仅针对已保存远端身份、创建校验阶段失败且正文尚未发送的首条投递，管理核验先 GET 核对原会话及历史，再通过受控事务恢复同一请求与后台任务。要求原账号有效、请求代次一致、正文仍在保留期、没有发送回执或用户事件、配置已核验，且任务未删除/终止。真实的未知消息 POST 不恢复重发，不新建远端会话、不改原文和请求号、不重复占用额度。

恢复事务采用会话先于投递行的锁顺序，并对反向路径已占用的投递行跳过等待。快照更新保留本地或远端终止状态，防止旧 GET 把已终止任务恢复成运行中。

UI 复用同一用户头像/气泡显示已保存任务正文；发送状态使用独立的灰色小字，请求号和错误码放入折叠详情。有已保存消息时不显示“等待任务开始”占位，收到上游消息后按回执去重。

## 验证

初始快照/消息显示回归先失败后通过。一次范围审查发现恢复/删除锁顺序和终止状态两项问题，四项回归先复现后修正、定向复核通过。

最终受影响范围一次检查：41 文件 / 683 测试通过（139.14 秒）；覆盖 Web、SDK、会话投递/API/数据库及隔离真实 PostgreSQL。真实并发恢复仅发送一次，错误所有权/代次/删除状态拒绝，删除阶段不会遇到恢复占用的反向投递锁，终止任务不重新排队。工作区构建含类型检查、修改文件 Lint/格式/diff 检查通过。

已通过受控方法恢复截图对应的原请求。实际读回确认 accepted、发送回执已记录、快照 verified、错误及未知标记清空，会话 running；保留同一个远端会话和请求号，未重复创建或投递。临时 PostgreSQL 已停止；未启动或停止用户开发服务，未截图或浏览器视觉检查。用户已有 material-picker 格式变动与 diagrams 保持原样。
