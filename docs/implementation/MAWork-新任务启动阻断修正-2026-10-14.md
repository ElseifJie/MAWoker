# 新任务启动阻断修正

起点 main `5000ae6`。截图中的新任务启用了个人记忆；实际账号的旧记忆 edit 仍处于 repairing，准入门禁拒绝新任务，页面却把 MEMORY_BUSY 统一显示成“任务无法启动，请重试”。只读核对确认无该次新投递记录，未重复提交截图中的研究任务。

沿用已通过真实 PostgreSQL CAS 与哈希回归验证的 MemoryService 恢复逻辑：仅在目标路径和远端内容哈希一致时核验旧发送步骤，禁止远端写入及未知结果重放。旧隔离已解除，后台进入新的自动整理流程；只读执行真实记忆准入 gate 成功，状态可用。未强制绕过门禁。

新任务页面对 MEMORY_BUSY / MEMORY_REPAIR_REQUIRED 显示明确原因，提供“修复个人记忆”链接及用户主动“关闭个人记忆”的选择。关闭只改变选择，不自动提交；任务要求、助手、材料与草稿保留，模式变化生成新请求标识。其他失败仍沿用原重试行为，不自动关闭记忆。

两项回归先失败后通过，一次范围审查无发现。最终受影响范围 5 文件 / 87 测试通过，覆盖实际 App/新任务入口、StrictMode、迟到响应、请求重放、个人记忆选择与输入法。Web 构建包含类型检查，通过；修改文件 ESLint、Prettier 和 diff 检查通过。后端实现未变，复用已有证据，不重复数据库或全项目测试。

未进行截图或浏览器视觉检查，未启动或停止用户开发服务；用户 material-picker 格式变动和 diagrams 未纳入提交。保留当前草稿后，用户重新点击“开始任务”即可进行自己的任务提交。
